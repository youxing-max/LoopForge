🛠️ LoopForge

让 AI 写代码这件事，像工厂流水线一样靠谱

它解决什么问题？

AI 写代码 = 不可信

😵 现状痛点：

  • 写代码的 AI 自己测自己 = 自吹自擂
  • 测试红了？改断言比改代码快 = 造假
  • 代码写完没人盯 = 出问题没人认

✅ LoopForge 的解法：

把"写 / 测 / 审"三件事锁给三个不同的人，互相看不见对方的工作区。

🏭 一句话理解

工厂流水线 + 互相不串岗

像汽车工厂：焊接工、车床工、质检员各管各的，谁也不能抢别人的活。

👥 9 个角色，干 3 件事

✍️ 写代码的（4 个）

  • goal-architect · 目标架构师 · 问清楚你要啥
  • req-interrogator · 需求拷问机 · 追问模糊点
  • srs-drafter · 需求文档起草员 · 把需求写死
  • design-author · 设计文档作者 · 画架构图
  • impl-coder · 码农 · 只写 src/

📝 写测试的（1 个）

  • test-author · 测试员 · 只写 tests/

🏃 跑测试的（1 个）

  • test-runner · 跑分员 · 只跑不写，汇报事实

🔍 审计的（3 个）

  • gate-checker · 门卫 · 机械检查清单 ✓✗
  • goal-auditor · 终审 · 双轮独立审计（fresh agent）
  • 主 Claude · 调度员 · 只传话，不干活

🔒 锁权限 · 关键一招

写代码的 跑不了测试
跑测试的 改不了代码
审计的 啥都不能动

不是靠"道德提醒"，是 工具菜单直接砍掉：

  • 码农 impl-coder：tools: [Read,Edit,Write,Grep,Glob] 无 Bash
  • 测试员 test-author：同上 无 Bash
  • 跑分员 test-runner：tools: [Read,Bash,Grep,Glob] 无 Edit/Write
  • 终审 goal-auditor：tools: [Read,Grep,Glob] 无 Bash 无 Edit

🔄 流水线长这样

0. 定目标
goal.md
→
1. 拷问需求
req-*
→
2. 写 SRS
srs-drafter
→
3. 写设计
design-author
→
4. 写→跑→改 循环
三方交替
→
5. 双轮审计
2 个 fresh agent
→
✅ 交付

🚧 Stage 4 内循环（最核心）：

test-author 写测试 → test-runner 跑 → 主 Claude 看报告 → fail 就派 impl-coder 改 → 再跑 → 全绿才放行

🚪 Goal 门 · 每阶段必须过

🚪G0
需求拷问够清
🚪G1
SRS 可机读
🚪G2
设计覆盖全
🚪G3
测试全绿
🚨G5
越权检测
🚪G4
双轮审计

🚨 G5 越权门最狠：事后 git diff 检查有没有人越权。发现 → 本轮作废 → 滚回去重派。

🆚 对比一下

普通 Claude Code：

😬 一个 AI 写 + 测 + 审 = 自欺欺人

LoopForge：

😎 9 个 AI 各管一摊 + 工具锁死 + 门卫把门 + 双轮审计

🎯 适合谁？

✅中大型项目
✅需求模糊但要交付
✅怕 AI 偷懒造假
❌一次性脚本
❌玩具 / MVP 试错
❌5 分钟小工具

⏱️ 安装

bash scripts/install.sh
↓
bash loopforge-init.sh （项目内）
↓
/loopforge 我要做 XXX

⚡ 两步 5 分钟装完

🎓 一句话总结

不是"提醒 AI 别作弊"
而是"让作弊做不到"
