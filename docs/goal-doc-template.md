# 项目目标书模板（Goal Doc Template）

> 这是 loopforge Loop 的**驱动器**。Stage 0.5 由 `goal-architect` agent
> 用本模板产出 `docs/loopforge/goal-doc.md`，与用户多轮 Q&A 直到用户确认。
>
> **这不是 SRS**（R-XX 单条需求），**不是设计**（接口/行为边界），**不是 goal.md**
> （判据清单）。它是**项目级**的流程化结构化分解：把模糊想法拆成可被 Stage 1~5
> 串起来执行的"项目地图"。

---

## 使用方法

1. **Stage 0.5 启动时**，`goal-architect` 按本模板填初版 → 写入 `docs/loopforge/goal-doc.md`
2. **主 Claude 把必答清单呈现给用户** → 用户回答
3. **循环改 goal-doc** → 直到用户说"确认，下一阶段"
4. **Stage 0.5 退出** = 用户确认 + goal-doc 七大章节无 [待确认]

---

## 0. 一句话定义

**用一句话告诉所有 agent 这个项目是做什么的**（不超过 30 字）。

```
<例如：实现一个支持单聊/群聊/文件传输的即时通讯系统>
```

> 这句话会被 Stage 1 的拷问官、Stage 2 的 SRS 起草者反复读到 —— 不清晰会让所有下游产物偏题。

---

## 1. 系统边界

**画出"谁在里面、谁在外面"**：

| 角色 | 在系统内？ | 备注 |
|:--|:--:|:--|
| 终端用户 | ✅ | ... |
| 客户端 App | ✅ | ... |
| 服务端 | ✅ | ... |
| 第三方登录 | ❌ 外部 | 调 XX 接口 |
| 推送服务 | ❌ 外部 | 调 XX 接口 |
| ... | ... | ... |

> 漏画的角色 Stage 1 拷问会反复追问。

---

## 2. 顶层子系统划分

**按"能不能独立验收"切**。每个子系统一行：

| 子系统 | 一句话职责 | 关键对外接口 | 优先级 |
|:--|:--|:--|:--|
| 账号体系 | 注册/登录/会话管理 | `POST /auth/login` | P0 |
| 单聊消息 | 点对点收发/已读回执 | `WS /msg/p2p` | P0 |
| 群聊消息 | 群组管理/消息广播 | `WS /msg/group` | P0 |
| 文件传输 | 上传/下载/缩略图 | `POST /file/upload` | P1 |
| 离线推送 | 离线消息推送 | `POST /push/send` | P1 |
| ... | ... | ... | ... |

**判据**：每个子系统都必须能独立起一份 `docs/loopforge/srs/<子系统>.md` 跑 Stage 4 Loop。

> **不要把"通用工具"当子系统**（如"日志""配置中心"），它们是横切关注点，归 Stage 0 goal.md 的全局门。

---

## 3. 里程碑与批次

**批次 0 永远是契约**。后续按依赖顺序：

| 批次 | 名称 | 验证组 runner | 子系统 | 依赖批次 | 状态 |
|:--|:--|:--|:--|:--|:--|
| 0 | **契约冻结** | `run_contract` | 所有对外接口签名 + 错误码 | — | ⏸ 待启动 |
| A | 账号 + 消息最小闭环 | `run_msg` | 账号 + 单聊 | 0 | ⏸ 待启动 |
| B | 群聊 | `run_group` | 群聊 | 0, A | ⏸ 待启动 |
| C | 文件 + 推送 | `run_extra` | 文件 + 推送 | 0 | ⏸ 待启动 |
| D | 集成 | `run_e2e` | 端到端 | A, B, C | ⏸ 待启动 |

**字段说明**：
- **批次 0 = 契约**：API schema / 数据结构 / 错误码枚举 / 模块边界。**冻结后所有批次不许改**
- **依赖批次全绿才能开工** —— 这条不能破
- **每个批次必须配一个 run_<组>.py**（可由 Stage 4 test-author 生成）

> 完整批次规则见 `<SKILL_DOCS>/large-project-guide.md`。

| D5 | 部署形态 | 容器/K8s / 裸机 / Serverless | ... | 用户 |
| ... | ... | ... | ... | ... |

### 4.2 每批次决策（仅影响该批次）

| 批次 | # | 决策 | 选项 | 当前选择 |
|:--|:--|:--|:--|:--|
| A | DA-1 | 消息持久化策略 | 同步写库 / 异步落盘 + 回放 | ... |

**`当前选择`列允许 [待用户拍板]**，但目标是不留 [待用户拍板] —— 用户审查时逐项拍。

## 5. 跨批次不变约束

**一旦定下来所有批次都遵守的契约**：

```
# 错误码体系
ERR_AUTH_INVALID_TOKEN = 40101
ERR_MSG_RATE_LIMIT     = 42901
...

# 接口命名规范
<资源>.<动词>   e.g. auth.login, message.send

# 时间/ID 规范
- 时间戳：UTC 毫秒
- 用户 ID：雪花算法 64-bit
- 消息 ID：UUID v7

# 安全基线
- 所有 API 必须 HTTPS
- 密码 bcrypt cost ≥ 12
- 输入校验：所有外部输入走 Pydantic/Bean Validation
```

> 这些会变成 `docs/loopforge/goal.md` 的**全局门**（G0.4 契约未破坏）。

## 6. 风险与未决

| # | 风险 | 等级 | 当前缓解 | 触发条件 |
|:--|:--|:--|:--|:--|

| R2 | 离线消息一致性 | 中 | 异步队列 + 幂等消费 | 弱网 30% 丢包 |
| ... | ... | ... | ... | ... |

**`当前缓解` 列空 = 没想清楚**。Stage 4 跑到对应批次时主 Claude 会回来追问。

---

## 7. 范围之外

**明确说不做什么** —— 比"要做什么"更重要：

```
- 视频通话 / 语音通话（P3 未来考虑）
- 朋友圈 / 状态（P3 未来考虑）
- 小程序生态（P3 未来考虑）
- 端到端加密（合规风险，先不做）
- 跨平台桌面客户端（移动优先）
- ...（用户补充）
```

> Stage 1 拷问官每次想做"顺手扩展"时会回来查这份清单。

## 附录 C：goal-doc 必须经历的检查

主 Claude 在 Stage 0.5 退出前自查：

- [ ] §0 一句话定义 ≤ 30 字且不模糊（"做一个聊天软件"是模糊，"实现即时通讯系统，支持单聊/群聊/文件传输"是不模糊）
- [ ] §1 系统边界无遗漏（终端用户/客户端/服务端/外部依赖至少各 1 行）
- [ ] §2 子系统 ≥ 1 行且每行能独立起一份 SRS
- [ ] §3 批次 0 = 契约冻结，且列出了所有后续批次
- [ ] §4 关键决策至少有 3 行（否则等于"还没想好做什么"）
- [ ] §5 不变约束至少 1 条（错误码/接口名/时间格式任一）
- [ ] §6 风险表允许空但必须有标题行
- [ ] §7 范围外 ≥ 1 条（否则等于"什么都做" —— 一定失败）
- [ ] 全文 `[待用户拍板]` 标记数 ≤ 3（再多 = 用户没真审查）
- [ ] 用户在对话里说过"确认，下一阶段" / 等价表述

## 附录 D：完整示例（"做一个微信"）

> 这是一份**真实形态的 goal-doc**，展示从"一句话模糊需求"到"可驱动 Loop 的项目目标书"。
> 注意：里面所有 `[用户已拍板]` 的值在真实场景里必须来自用户回答，不许 agent 自封。

```markdown
# 微信级 IM 系统 Goal Doc

## 0. 一句话定义

实现即时通讯系统，支持单聊/群聊/文件传输/离线消息。

## 1. 系统边界

| 角色 | 在系统内？ | 备注 |
|:--|:--:|:--|
| 终端用户 | ✅ | 消费者，预估 10 万 DAU |
| 移动客户端（iOS/Android） | ✅ | 第一版交付 |
| Web 客户端 | ❌ 范围外 | 见 §7 |
| IM 服务端 | ✅ | 本项目主体 |
| 文件存储 | ❌ 外部 | 对象存储 S3 兼容 |
| 推送服务 | ❌ 外部 | APNs / FCM |
| 短信验证码 | ❌ 外部 | 第三方短信网关 |

## 2. 顶层子系统划分

| 子系统 | 一句话职责 | 关键对外接口 | 优先级 |
|:--|:--|:--|:--|
| 账号体系 | 注册/登录/会话管理 | POST /auth/login | P0 |
| 单聊消息 | 点对点收发/已读回执 | WS /msg/p2p | P0 |
| 群聊消息 | 群组管理/消息广播 | WS /msg/group | P0 |
| 文件传输 | 上传/下载/缩略图 | POST /file/upload | P1 |
| 离线消息 | 掉线期间消息暂存与补推 | GET /msg/offline | P1 |
| 好友关系 | 添加/删除/黑名单 | POST /friend/add | P1 |

## 3. 里程碑与批次

| 批次 | 名称 | 验证组 runner | 子系统 | 依赖批次 | 状态 |
|:--|:--|:--|:--|:--|:--|
| 0 | 契约冻结 | run_contract | 全部 API schema + 错误码 | — | ⏸ |
| A | 账号+单聊最小闭环 | run_msg | 账号 + 单聊 | 0 | ⏸ |
| B | 群聊 | run_group | 群聊 | 0,A | ⏸ |
| C | 文件+离线+好友 | run_extra | 文件/离线/好友 | 0,A | ⏸ |
| D | 端到端集成 | run_e2e | 全部 | A,B,C | ⏸ |

## 4. 每批次的关键决策

### 4.1 全局决策

| # | 决策 | 选项 | 当前选择 | 决定人 |
|:--|:--|:--|:--|:--|
| D1 | 服务端语言 | Java/Spring · Go/Gin · Python/FastAPI | Java/Spring [用户已拍板] | 用户 |
| D2 | 数据库 | PostgreSQL · MySQL | PostgreSQL [用户已拍板] | 用户 |
| D3 | 消息下发协议 | WebSocket · HTTP 长轮询 | WebSocket [用户已拍板] | 用户 |
| D4 | 鉴权 | JWT · Session | JWT [用户已拍板] | 用户 |
| D5 | 部署 | K8s · 裸机 | K8s [待用户拍板] | 用户 |

### 4.2 批次决策

| 批次 | # | 决策 | 当前选择 |
|:--|:--|:--|:--|
| A | DA-1 | 消息持久化 | 异步落盘 + 回放 [待用户拍板] |
| B | DB-1 | 群成员上限 | 500 [用户已拍板] |

## 5. 跨批次不变约束

```
# 错误码体系（五位：HTTP 状况 + 业务码）
ERR_AUTH_INVALID_TOKEN = 40101
ERR_MSG_RATE_LIMIT     = 42901

# 接口命名
<资源>.<动词>  e.g. auth.login, message.send

# 时间/ID
时间戳：UTC 毫秒 · 用户ID：雪花 64-bit · 消息ID：UUID v7

# 安全基线
全 API HTTPS · 密码 bcrypt cost≥12 · 外部输入走 Bean Validation
```

## 6. 风险与未决

| # | 风险 | 等级 | 当前缓解 | 触发条件 |
|:--|:--|:--|:--|:--|
| R1 | 大群消息扇出性能 | 高 | 批次 D 压测 | 单群 500 人同时发 |
| R2 | 弱网离线消息丢失 | 中 | 幂等消费 + 补推 | 30% 丢包模拟 |
| R3 | D5 部署形态未定 | 低 | [待用户拍板] | 批次 A 开工前 |

## 7. 范围之外

- 视频/语音通话（P3 未来）
- 朋友圈/状态（P3 未来）
- 小程序生态（不做）
- 端到端加密（合规风险，先不做）
- Web 客户端（移动优先，二期）
- 桌面客户端（不做）
```
